# Executable RELEASE_COMMIT — supporting adapter guide

Optional `scripts/release_commit.py` implements the existing conversational RELEASE_COMMIT meaning from [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md) and [MIGRATION_AND_RELEASE_POLICY.md](MIGRATION_AND_RELEASE_POLICY.md). It is not a policy owner. [EXECUTION_FACADE.md](EXECUTION_FACADE.md) owns dispatch; the project profile owns applicability, commands/gates/approval requirements and message convention. No approval, closure, roadmap transition, publication, production or preview is supplied by this adapter.

## Surface and applicability

The opt-in reference provides read-only `./run.sh commit-identity` and `./run.sh commit-preflight`, and mutating `./run.sh release-commit`. Uppercase RELEASE_COMMIT remains a conversational token, not a shell command. Equivalent entrypoint: `python3 -B scripts/release_commit.py identity|preflight|commit`. This assignment's implementation permission is not permission to commit its own candidate with this interface.

Project-owned release-commit-profile.json schema 1 has exact fields: schema_version, external state_root, version_path, lifecycle_path (JSON status), allowed_states (DRAFT/RC/FINAL), required_gates, test_gates, required_approvals (COMMIT mandatory; SEMANTIC/CLOSURE when applicable), and message_pattern. Configure required local/stronger gates deliberately. Lifecycle is identity, not human approval; no universal FINAL or closure-before-commit mandate is introduced. The reference requires COMMIT and SEMANTIC decisions. Projects requiring closure also add CLOSURE; other approvals remain independent. A consumer must not silently drop a required local gate. Configuring these files does not by itself accept the adapter or authenticate authority.

Only regular tracked files and a normal attached branch are supported. Symlinks, submodules, unmerged/merge/rebase/cherry-pick state, unverified records, unrelated changes and missing metadata hold execution. Actual active Git hooks/custom hooksPath, applicable external clean filters/fsmonitor and required signing cause NOT CONFIGURED/PENDING before source diagnostics: this narrow plumbing adapter cannot run them safely or satisfy their extra acceptance. It rejects rather than disabling those obligations. Projects needing hooks/signing require a separately accepted adapter. Standard Git >=2.31 with --path-format support, Python >=3.11 and stdlib are the local prerequisites; unsupported Git fails closed. No branch/provider/OS name is hard-coded.

## Preparing exact identity without mutation

Owner/operator first reviews and explicitly stages the intended bounded files. The adapter never runs add, reset, stash, checkout, clean, amend, merge, rebase, push or tag. All changed files must be staged completely; unexpected nonignored untracked or unstaged files and unexpected staged scope fail closed. Ignored runtime/secret/artifact files are outside this source contract and never staged, hashed or echoed. Projects must keep valid ignore/exclusion rules; this is not a secret detector or hostile-repository sandbox.

Example with synthetic names (not authorization):

```sh
./run.sh commit-identity --work-unit UNIT-A --file path/to/changed-file --message "Finalize validated candidate"
./run.sh commit-preflight --work-unit UNIT-A --candidate /private/candidate.json --evidence /private/evidence.json --approval /private/approval.json
./run.sh release-commit --work-unit UNIT-A --candidate /private/candidate.json --evidence /private/evidence.json --approval /private/approval.json --owner-confirmed APPROVAL_SHA256 --authorization-reference OWNER_DECISION_REFERENCE
```

`identity` returns `IDENTITY_ONLY` and a candidate object. A trusted operator retains that object as an external candidate JSON; this read-only operation creates no file/object/ref or acceptance. Identity binds local repository-root hash, attached branch, exact HEAD, raw index SHA-256, complete stage-entry digest, all indexed source member hashes/modes, exact file scope, work-unit ID, message, version/lifecycle, configuration, Git executable/configuration and adapter bytes. Candidate IDs hash sorted compact JSON. Moving a checkout, modifying Git identity/configuration or refreshing the raw index invalidates approval; prepare a new truthful record. Git-root paths/user identity/configuration contents are not printed, only hashes. Dormant global filters without applicable file attributes are permitted; applicable staged/worktree clean filters are rejected before source diagnostics. External diff/textconv execution is explicitly disabled for diagnostic diff commands.

## Evidence and human authority

Evidence/approval/receipt files must be outside source in private project/operator-owned storage, never staged into the candidate. This avoids evidence/approval self-reference. A source change to include a new reviewed decision document requires a newly validated candidate. `state_root` must neither contain nor overlap source, including through symlinks. Executed attempts retain private receipts (0600) in a private root (0700); no automatic cleanup or retry of an ambiguous attempt.

Evidence JSON exact fields: schema_version=1, candidate_sha256, work_unit, gates. Gates must equal the configured required_gates; each records status=PASS, exit=0, actual command/runtime strings, passed/failed/skipped integer counts. All failed/skipped values must be zero; configured test_gates require nonzero passed. Missing, unrun, empty-test, skipped, failed or stale evidence is rejected. The adapter checks recorded results/identity; it does not run validation or prove that a report is honest. The calling actor must verify trusted real command/job artifacts under TEST-IDENTITY before using these records. No trusted evidence is generated from an unchecked PASS claim.

Approval JSON exact fields: schema_version=1, candidate_sha256, evidence_sha256 (exact evidence file bytes), work_unit, decisions. Decisions must equal configured required_approvals. Each has status=APPROVED, role=human_owner, reference (bounded stable ID), reviewed_candidate_sha256, and finite future expires_at (Unix time). The owner/project selects review expiry; the adapter introduces no universal expiry duration. PENDING, AI Supervisor role, missing/wrong/expired decisions or different candidate/evidence hashes are rejected. Stale approvals cannot be reused merely by editing their hash fields: a new actual human decision is required.

A packet/file/status/role assertion is NOT authentication. The approved project channel remains the authority. Before mutation the invoking actor must independently verify the actual owner decision for these exact bytes and provide `--owner-confirmed` equal to the approval file SHA-256 AND `--authorization-reference` equal to the recorded COMMIT decision reference. This is an explicit operator assertion that the external human channel was checked, not a signature, approval service, shared-account check or new delegated AI power. Without that assertion mutation is rejected. A forged local record and forged operator assertion cannot be detected by an unsigned local adapter; such use violates canonical policy. Protected approval authentication/transport is out of scope.

Preflight returns ELIGIBLE only for mechanically consistent approved records and unchanged identity; it writes nothing and confers no mutation authority. Work-unit identity is bound across source/evidence/approval/invocation; it does not edit or interpret live CURRENT/NEXT. Commits after a separately authorized closure may refer to the just-closed unit, so CURRENT need not still name it. That authority must be verified through the owner channel, not inferred from this adapter.

## Actual Git mutation and races

Commit requires all preconditions plus the independent owner-channel assertion. It acquires the real index.lock exclusively (never reclaims another writer), repeats preflight, copies the accepted index to private disposable storage and uses write-tree/commit-tree against the exact approved parent. It stages nothing and does not modify real index bytes. It rechecks evidence/approvals/source/branch before update-ref, using expected old HEAD as compare-and-swap. Cooperating Git index writers cannot change the accepted index during this interval; a concurrently advanced ref cannot be overwritten. A failed attempt may leave an unreachable Git object; it is retained, not cleaned or mistaken for a successful ref update.

No hooks/signing are executed; incompatible requirements are rejected before mutation. Configured Git author identity is used without claiming verified legal identity. There is no shell evaluation or arbitrary command mapping from the approval. The exact reviewed message is used literally. Raw Git/exception output is suppressed; only bounded hashes/status/ref/identity reports are returned.

After an attempt, observe actual HEAD/branch/index/tree/parent and worktree state even on nonzero failure. Only a matching new commit with approved parent/tree, unchanged real index and clean source is COMMITTED. Otherwise return ATTEMPT_REQUIRES_REVIEW (exit 3); preserve actual state without rollback. A nonzero result never proves no mutation. Missing post-operation observation is PENDING and demands manual inspection. Post-commit status/config reads are diagnostics, not validation/retest/rebuild.

A successful receipt makes a repeat invocation ALREADY_COMMITTED, no new commit, only while records remain valid, the supported Git environment/configuration is reverified BEFORE status diagnostics, and exact recorded HEAD/branch/index and clean source match. Changed Git configuration or newly configured helpers hold the repeat without executing them. Failed/ambiguous attempts or later drift require review; no automatic replay. Receipts are unsigned local evidence, not human authority. Index locking and ref CAS do not sandbox malicious same-user writers, externally changed refs/configs or Git code; use a trusted exclusive project context. Concurrent changes after the last observation are outside any local snapshot guarantee.

Exit 0 means identity/preflight success or COMMITTED/ALREADY_COMMITTED as declared in JSON, never closure/publication acceptance. Exit 3 means missing/unavailable/stale/unsupported/failed preconditions or an ambiguous attempt. RELEASE_PREVIEW remains NOT CONFIGURED; no push/tag/release/publication call exists.
