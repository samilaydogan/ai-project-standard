# Optional committed-identity preview adapter

Canonical semantics remain WF-SCOPE in AGENT_WORKFLOW.md and REL-ARTIFACT in MIGRATION_AND_RELEASE_POLICY.md; testing truth/identity remain TESTING_AND_EVIDENCE.md. This supporting adapter owns no policy, approval or CURRENT/NEXT. PROJECT_PROFILE declares applicability. Release preview is separately authorized; a commit decision never substitutes for PREVIEW approval.

## Executable surface and identity

`./run.sh preview-identity --commit FULL_SHA --work-unit UNIT` reads only Git objects and the committed release-preview-profile.json. `preview-preflight` adds `--approval /absolute/external/approval.json`. `release-preview` additionally requires `--owner-confirmed APPROVAL_FILE_SHA256 --authorization-reference OWNER_REFERENCE` and performs isolated execution. Identity/preflight are read-only; run creates temporary isolated state, never stages/commits/updates source refs. Missing/malformed/unprovable inputs exit 3 PENDING. Run failures exit 1, proven scoped success exit 0. No omitted prerequisite becomes PASS.

This adapter supports Git SHA-1 repositories (40-character commit IDs); SHA-256 repositories require another accepted adapter. Full 40-character commit must equal observed source HEAD on an attached branch. Identity binds repository path hash, branch/ref, commit/tree, work unit, committed profile and standard manifest bytes, committed VERSION, executing adapter bytes and actual Python executable/runtime. Portable path validation rejects drive/colon paths, case aliases of .git, trailing dot/space aliases and Windows device names before joining/materialization. Case/Unicode-normalization collisions at file or directory prefixes are rejected rather than overwriting committed inputs; runtime .env and metadata case aliases are also rejected. All materialized files are exact committed ordinary blobs/modes; no archive export-ignore behavior, symlinks, submodules or .git. Config cannot come from a dirty worktree. Bounded materialization supports at most 10,000 ordinary files, 16 MiB per blob and 64 MiB total; larger projects require an accepted adapter/configuration change. Missing committed profile is NOT CONFIGURED/PENDING, including an older commit lacking this adapter configuration. Version equality does not imply manifest release integrity or release eligibility; normal standard checker remains independent.

Committed profile schema 1 supports only `trusted-stdlib-python-validation`, a committed Python entrypoint, literal argument list, 1–180 second timeout, committed-file prerequisites, version_path and standard_path. Unsupported runners, dependencies, installers, Docker and service orchestration are NOT CONFIGURED. No resolver/imported site packages are supplied. Profile and arguments are approved trusted inputs, not a shell command or permission for external data. Existing source-exclusions.json rejects committed excluded runtime/secret/cache files before extraction, with its declared source exceptions; runtime .env and non-waivable .DS_Store cannot be re-admitted; nested multi-component directory patterns are enforced; this is not a general secret detector.

## Separate authorization

External JSON fields exactly: schema_version 1, kind PREVIEW, status APPROVED, role human_owner, reference (bounded safe identifier), identity_sha256 (canonical sorted compact identity JSON SHA-256), expires_at (Unix seconds, future and within 24 hours). Hash/role/file presence do NOT authenticate the human, honest code, truthful reports or channel. The operator must independently verify the actual authorized owner channel for this exact identity and reference before explicitly confirming file hash. Stale identity/config/HEAD/work-unit/adapter/runtime, expired record, COMMIT-only record or missing confirmation fails closed. Read-only preflight ELIGIBLE is not execution/approval. No semantic/adoption/closure/exception/publication/production approval is created.

## Isolation and evidence

Temporary storage inside source is rejected. Each run creates a new private temporary directory containing committed source, empty HOME and temporary state. Child Python runs with `-I -S -B`, no inherited credentials, proxy, .env, PATH or package environment, no stdin and raw stdout/stderr discarded. Source worktree/index/refs/files (including ignored and untracked file identities) are observed before/after; dirty/staged/untracked/ignored bytes are preserved and do not enter extraction. Source and approval identity are checked again immediately before launch. Concurrent change rejects or marks result FAIL; this does not lock hostile writers.

The trusted validation child receives only PREVIEW_RESULT_PATH and a fresh PREVIEW_NONCE plus isolated HOME/TMPDIR and locale. It must write bounded JSON with exactly nonce/startup/health/stop, boolean evidence for each phase. PASS requires actual zero exit plus all three true, matching nonce, cleanup and unchanged source. A zero exit, old report, malformed evidence, missing health, skip or raw logs cannot establish PASS. Nonce prevents accidental stale reuse; it does not authenticate a malicious validator. Results retain only allowlisted statuses, identity and hashes, never raw child output/approval content. The caller may preserve this sanitized JSON outside source or in an explicitly authorized project evidence artifact. Temporary source/runtime state is always cleaned, no retention option or reused output. A fresh invocation runs again without source mutations or persistent service state.

Reference scripts/preview_health.py loads committed health_scaffold.py, starts an actual stateless HTTPServer at loopback port 0, probes the owned server with proxies disabled, checks the exact health body and shuts down/joins before reporting. No stale fixed-port server is accepted. Fixture interface validators are synthetic evidence only; the actual reference HTTP test is the local startup/health acceptance. This is not deployment/production acceptance.

## Limits and failure handling

Trusted, reviewed, bounded stdlib single-process validators only. Runtime isolation is not an OS filesystem/network/security sandbox; malicious Python can access ambient filesystem/network through code and cannot be made safe by this adapter. Entrypoints must not spawn descendants, detach servers, access source/shared data or use real credentials; such runners require a separately accepted adapter and remain unsupported. Python isolated mode excludes sitecustomize; it is not a generic network firewall. Reference code uses only loopback/synthetic stateless data. Timeout kills/waits the owned validation process; hard descendant/process-tree termination is not supported. Startup/health/stop remain NOT ASSESSED on timeout or absent report; no fabricated stop acceptance. OSError/malformed reports produce failure, cleanup runs through TemporaryDirectory. Precondition/race failures may return PENDING without a runtime result; actual source changes are never reset/discarded. No push/tag/release/commit/deploy commands exist in the control.
