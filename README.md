# AI Project Standard

Version **0.1.0**: intended first public version. Final content readiness is recorded in `docs/RECONCILIATION_VALIDATION.md` (source-repository audit record); no Git tag/publication is implied. A lightweight generic engineering/governance product, with no application runtime or package manager.

Start with [ownership and precedence](DOCUMENT_GOVERNANCE.md), [workflow](AGENT_WORKFLOW.md), [adoption](ADOPTION.md) and [rule registry](POLICY_RULES.json). [CHANGELOG.md](CHANGELOG.md) distinguishes extraction from new policy. Source-only `docs/PROVENANCE.md`, `docs/NEW_POLICY_REGISTER.md`, `docs/EXTRACTION_MATRIX.md` and audit reports are non-distributed historical/reconciliation evidence.

The schema-2 release manifest hashes the exact distribution inventory; it excludes itself and audit reports to avoid self-reference. Copy its required invariant set unchanged, instantiate all required Markdown templates, optional state JSON and adoption JSON. Store all distribution files plus manifest in the consumer's pinned companion snapshot. Local profile rules may strengthen the baseline; eligible deviations require narrow reviewed exceptions. See ADP-INTEGRITY/STRUCTURE/EXCEPT.

Tooling requires Python 3.11 or newer. Validation: `python3 -B scripts/generate_release.py --check`, `python3 -B scripts/check_standard.py --standard .`, `python3 -B scripts/check_docs.py .`, `python3 -B -m unittest discover -s tests -v`, and `git diff --check` plus untracked-file whitespace review. The generator deterministically creates or verifies the documented distribution manifest; it does not declare semantic approval or publish content. READY requires reconciliation, accurate provenance, owner/waiver consistency and passing quality/negative checks. Consumer acceptance additionally needs a recorded decision for the exact pin. Runtime/release acceptance is separate.

Docs checks are bounded: scan explicit `.md`/`.json` files or visible Markdown/JSON excluding any hidden path, symlink file, or path component named `vendor`, `node_modules`, `build`, `dist`, `data`, `postgres-data`, `backups`, `__pycache__`; check supported inline local links and non-template placeholders. Standard distribution vocabulary scanning runs only when a release manifest is present; consumer project vocabulary is allowed. Supported links are inline `[label](path)`, `[label](<path with spaces>)` and these forms with a quoted title. Images, reference links, fenced/inline code, heading targets and external URLs are outside this check. Relative file paths are existence-checked; anchors are not verified. Placeholder scanning covers scanned Markdown/JSON, except filenames containing `.template.`. Vocabulary checks scan every release-listed Markdown/JSON/Python text for the configured source-project term/roadmap pattern; scripts' explicit vocabulary-list literal is the sole allowlisted occurrence. This lexical screen cannot prove generic semantics or full correctness. Output reports each actually executed scope, and failures identify file/rule. Use `--files` for affected-document checks. Policy owners are TEST-APPLICABILITY and ADP-STRUCTURE.
