# AI project standard

Unreleased v0.2.0 runnable foundation: one normal execution facade, explicit toolchain/dependency, data/recovery/security/test applicability and operational documents. v0.1.1 was superseded before publication; its bounded work is preserved. Historical 0.1.0 remains intact. Canonical owner: [EXECUTION_FACADE.md](EXECUTION_FACADE.md); fixed machine contract: [execution-profile.json](execution-profile.json) and [PROJECT_PROFILE.template.md](PROJECT_PROFILE.template.md).

The default is native Mode A and help. Run ./run.sh help, ./run.sh doctor, ./run.sh test, ./run.sh lint. ./run.sh dev (or start) serves only health on explicitly declared 127.0.0.1:8080/health; Ctrl+C stops it. Bash/Python >=3.11 and stdlib only; no keys, DB, business logic or automatic dependency install. Optional runtime-local .env overrides safe values declared in [.env.example](.env.example); required keys and secret keys are empty in this example. .env is ignored, never generated by doctor, tracked or shipped with secrets. Process environment wins over local env; explicit reference CLI flags win over both. Test binds disposable loopback; bounded lint checks Python syntax/whitespace only.

Docker is explicitly NOT APPLICABLE in the default profile. In a new/disposable project, select [execution-profile.docker.json](execution-profile.docker.json) as execution-profile.json to opt into [compose.yaml](compose.yaml)/[Dockerfile.scaffold](Dockerfile.scaffold). The JSON-form Compose file is valid YAML and statically checkable with stdlib. Validate docker compose config separately. Start through ./run.sh dev only when Docker and the base image/build context are safely prepared: image acquisition is explicit, not a doctor action. The minimal non-root read-only service has no volumes/secrets/provider services. Host bind is 127.0.0.1; container listen is 0.0.0.0, each with explicit ports. This file's presence does not activate Docker. Static checker supports JSON-compatible Compose declarations, not arbitrary YAML; health/runtime acceptance is separate.

Mode A edits the worktree directly; Mode B receives versioned full/delta APPLICATION packages from an optional external producer. Both use installed ./run.sh. A separate apply_package.sh bootstrap role may precede installation; no generic installer implementation is supplied. Application package apply is distinct from pip/npm/dependency install/resolution. PROJECT_PROFILE declares applicability and external configurable apply-state/artifact roots; previous/rollback/staging folders are not a desirable source-tree pattern. See [MIGRATION_AND_RELEASE_POLICY.md](MIGRATION_AND_RELEASE_POLICY.md).

Integrity: python3 -B scripts/generate_release.py --check and python3 -B scripts/check_standard.py --standard . . Bounded docs: python3 -B scripts/check_docs.py . ; links/non-template placeholders/JSON syntax only. Vocabulary/project-neutrality, facts, URLs/anchors/images/reference links, real secret-content detection, runtime/provider/recovery acceptance are NOT ASSESSED by that docs checker. Profile checks never execute consumer commands or install dependencies.

Instantiate/merge project-owned templates/reference runtime assets, copy invariant policy/checkers/dispatcher and the complete pinned companion. [ADOPTION.md](ADOPTION.md) separates integrity, structure, recorded semantic approval and runtime acceptance. [POLICY_RULES.json](POLICY_RULES.json) owns exact inventory; [DOCUMENT_GOVERNANCE.md](DOCUMENT_GOVERNANCE.md) owns precedence. Reports/provenance under docs are repository-only. [OPERATIONAL_TOOLING_SCOPE.md](OPERATIONAL_TOOLING_SCOPE.md) explicitly defers broader reusable builders/evidence/QA/recovery to v0.3.0.

READY/FINAL is validated local content, not published release or application acceptance. No automatic commit/tag/push/adoption. These new generic decisions are explicit; stronger consumer gates remain local.

The schema-3 foundation is a fixed machine projection, not a policy DSL. See [installation](INSTALLATION.md), [migration/recovery](MIGRATION_RECOVERY.md), [operations](OPERATIONS_RUNBOOK.md), [third-party inventory](THIRD_PARTY_LICENSE_INVENTORY.md), and [exclusions](source-exclusions.json). `./run.sh status` / `health` probe local reference health only; unavailable health is PENDING, never a service start. Test isolation is a bounded reference harness, not a generic production acceptance runner. Static hashes bind reviewed manifest/lock bytes; adapters do not solve dependencies or establish license correctness. Fresh stateless reference is runnable before domain code; PENDING stateful tools prevent operational acceptance of those capabilities.
